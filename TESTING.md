# Тестирование приложения Focus

## Сброс онбординга для тестирования

Чтобы снова увидеть экран приветствия и протестировать запрос разрешений:

### Метод 1: Через DevTools (в браузере)
1. Откройте приложение в браузере
2. Нажмите F12 (открыть DevTools)
3. Перейдите на вкладку **Application** (или **Приложение**)
4. В левой панели выберите **Local Storage** → ваш домен
5. Найдите ключ `onboarding_completed`
6. Кликните правой кнопкой и выберите **Delete**
7. Обновите страницу (F5)

### Метод 2: Через консоль браузера
1. Откройте приложение
2. Нажмите F12 (открыть консоль)
3. Выполните команду:
   ```javascript
   localStorage.removeItem('onboarding_completed');
   location.reload();
   ```

### Метод 3: Очистить все данные приложения
1. В Chrome на Android: Настройки → Конфиденциальность → Очистить данные
2. Или удалить и переустановить PWA

## Тестирование запроса разрешений

### Что должно происходить:

1. **При первом запуске**:
   - Появляется экран приветствия
   - После "Начать" показывается экран разрешений
   - Синяя подсказка: "При нажатии кнопки браузер запросит разрешения..."

2. **При нажатии "Разрешить доступ"**:
   - Кнопка меняется на "Запрашиваем доступ..."
   - Синяя информационная панель: "Ожидание разрешения от браузера..."
   - **Браузер показывает системный диалог** для камеры
   - После разрешения - зеленая галочка ✓ у камеры
   - **Браузер показывает системный диалог** для микрофона
   - После разрешения - зеленая галочка ✓ у микрофона
   - Автоматический переход на экран туториала

3. **Если отклонить разрешение**:
   - Красная панель с ошибкой
   - Текст: "Доступ к камере/микрофону был отклонён"
   - Подсказка: "При нажатии на кнопку ниже браузер покажет диалог..."
   - Можно попробовать снова нажать "Разрешить доступ"

4. **Если нажать "Пропустить"**:
   - Онбординг завершается
   - Приложение откроется, но без разрешений
   - Разрешения будут запрашиваться при попытке использовать камеру/микрофон

## Тестирование на Android

### Проверка HTTPS (важно!)
Для тестирования разрешений на реальном Android устройстве нужен HTTPS. Варианты:

#### Вариант 1: Локальная сеть (только для базового тестирования)
```bash
npm run dev
```
Откройте `http://192.168.x.x:3000` на Android

⚠️ **Ограничение**: Некоторые браузеры на Android могут ограничивать getUserMedia через HTTP даже в локальной сети.

#### Вариант 2: ngrok (рекомендуется)
```bash
npm run dev
# В другом терминале:
ngrok http 3000
```
Используйте HTTPS ссылку от ngrok на Android

#### Вариант 3: Cloudflare Tunnel
```bash
npm run dev
# В другом терминале:
cloudflared tunnel --url http://localhost:3000
```

#### Вариант 4: Production deployment
Задеплойте на Vercel/Netlify/GitHub Pages для полноценного HTTPS

## Сброс разрешений (для повторного тестирования)

### Chrome на десктопе:
1. Нажмите на иконку замка/информации слева от URL
2. Выберите "Site settings"
3. Сбросьте Camera и Microphone на "Ask"
4. Перезагрузите страницу
5. Очистите localStorage (см. выше)

### Chrome на Android:
1. Нажмите на иконку замка в адресной строке
2. Выберите "Permissions"
3. Сбросьте Camera и Microphone
4. Или: Настройки → Сайты → найти ваш сайт → Разрешения → Сброс
5. Очистите localStorage через DevTools (подключите Chrome DevTools через USB)

### Полный сброс PWA:
1. Удалите приложение с домашнего экрана
2. Chrome → Настройки → Сайты → найти сайт → Очистить данные
3. Переустановите PWA

## Известные проблемы

### Разрешения не работают через HTTP
**Решение**: Используйте HTTPS (ngrok, Cloudflare Tunnel, или production deployment)

### Диалог не появляется повторно после отклонения
**Причина**: Браузер блокирует повторные запросы разрешений
**Решение**: Сбросить разрешения в настройках браузера (см. выше)

### На iOS Safari разрешения работают иначе
**Причина**: iOS Safari имеет другую политику разрешений
**Решение**: На iOS разрешения запрашиваются при первом вызове getUserMedia, не заранее

### Service Worker не обновляется
**Решение**: Hard refresh (Ctrl+Shift+R) или закройте все вкладки и откройте снова
